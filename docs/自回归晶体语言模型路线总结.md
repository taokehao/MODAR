# 自回归晶体语言模型路线总结

本文档总结当前项目中新开的“自回归晶体语言模型”路线。该路线与 FlowMM / DiffCSP 晶体原生生成路线并行推进，互不替代、互不阻塞、互不修改对方的模型代码、配置、缓存和 checkpoint。

## 1. 背景与动机

当前项目的核心目标是做实验表征条件下的晶体结构解析：

```text
PXRD / neutron / XRF / XPS-valence / optional lattice -> crystal structure
```

原有主线使用 FlowMM / DiffCSP 这类晶体原生模型，它们直接在晶胞、分数坐标、原子类型、周期边界和图结构上建模。这一路线物理上更自然，但训练和工程复杂度较高。

我们新增的自回归路线想验证另一个问题：

```text
能否把晶体结构解析变成一个“条件 prompt -> 晶体结构文本”的语言模型任务？
```

也就是说，让模型像写文本一样，逐 token 生成一个规范化的晶体结构描述。

这条路线不是为了取代 FlowMM，而是为了提供一个轻量、快速、可解释、便于做 ablation 的语言模型 baseline。它的价值主要在于：

- 快速验证“多模态谱图条件 -> 晶体结构序列”的可行性；
- 支持 Transformer / GPT 类模型；
- 训练成本低，迭代速度快；
- 后续可以自然扩展到更大模型、谱图 encoder、reward reranking 和 reward-weighted SFT；
- 能与 FlowMM 在相同 MP+WBM 数据和相同 ablation 条件下对比。

## 2. 与 FlowMM 的关系

必须明确：

```text
自回归语言模型路线与 FlowMM 路线并行。
```

本路线遵守以下约束：

- 不修改 FlowMM / DiffCSP 的模型代码；
- 不修改 FlowMM 的配置；
- 不写入 FlowMM 的 checkpoint 或缓存目录；
- 只读复用现有的 MP+WBM 多模态数据；
- 输出自己的序列数据、日志和 checkpoint；
- 后续评估可以共享 StructureMatcher、PXRD 回算、neutron 回算等评价工具。

当前已创建项目规则：

```text
.cursor/rules/language-model-route.mdc
```

其作用是提醒后续所有操作：语言模型路线保持独立，不干扰 FlowMM 主线。

## 3. 为什么先不使用 SLICES

前面讨论过 SLICES 的优点和局限：

- SLICES 擅长表达元素组成、连接拓扑和周期连接关系；
- 它不直接记录晶胞参数、键长、键角、原子坐标；
- 对 PXRD / neutron 结构解析来说，最终必须得到可回算谱图的三维结构；
- 如果输出只用 SLICES，还需要额外解码器恢复晶胞和坐标。

因此第一版没有采用 SLICES 作为主输出，而是采用更直接的：

```text
canonical CIF-like crystal tokens
```

它本质上是一个简化、规范、容易解析的 CIF-like 结构语言，直接输出：

- 分子式 / 组成；
- 原子数；
- 空间群编号；
- 晶胞参数；
- 原子类型；
- 分数坐标。

后续如果需要，可以加入局域环境、配位数、键长统计、畸变程度等辅助 token，但第一版先保持最小可用。

## 4. 第一版序列设计

### 4.1 总体形式

每个训练样本是一条自回归序列：

```text
<BOS>
<TASK> solve_structure
<COND_START>
  条件信息
<COND_END>
<CRYSTAL_START>
  晶体结构 token
<CRYSTAL_END>
<EOS>
```

训练时，条件部分作为 prompt，主要只对 `<CRYSTAL_START>` 之后的结构部分计算 loss。

推理时，模型看到：

```text
<BOS> <TASK> solve_structure <COND_START> ... <COND_END>
```

然后逐 token 生成：

```text
<CRYSTAL_START> ... <CRYSTAL_END>
```

### 4.2 条件输入块

当前支持以下条件块：

```text
PXRD
neutron diffraction
element set
XRF mass fraction
XPS valence
exact formula
known lattice
```

#### PXRD

第一版不直接输入完整连续谱图，而是先做峰提取，形成紧凑 peak tokens。

示意：

```text
<PXRD_START>
<PEAK> t 2 7 . 3 2 i 1 . 0 0 0 w 0 . 1 2 0
<PEAK> t 3 1 . 6 8 i 0 . 5 2 0 w 0 . 1 4 0
<PXRD_END>
```

其中：

- `t` 表示 2θ 位置；
- `i` 表示归一化强度；
- `w` 表示估计峰宽。

数字被拆成字符 token，例如 `27.32` 会变成：

```text
2 7 . 3 2
```

这样做可以显著减小词表大小。

#### 中子衍射

中子衍射使用与 PXRD 类似的 peak grammar，但 modality 单独标记：

```text
<NEUTRON_START>
<PEAK> t ...
<NEUTRON_END>
```

这样模型可以学习：PXRD 和 neutron 的峰位约束同一个晶胞，但强度来自不同散射因子，因此对原子类型和位置的约束不同。

#### 元素集合

元素集合只提供元素种类，不提供精确比例：

```text
<ELEMENT_SET> Na Cl
```

用于评估：

```text
PXRD + element set
```

是否比 PXRD only 更接近真实结构。

#### XRF

XRF 作为软组成约束：

```text
<XRF_START>
<XRF_MASS_FRAC> Na 0 . 3 9 3
<XRF_MASS_FRAC> Cl 0 . 6 0 7
<XRF_END>
```

它不等同于 exact formula，但能帮助模型推断元素比例。

#### XPS-valence

XPS-valence 表示价态或氧化态信息：

```text
<XPS_VALENCE_START>
<VALENCE> Na 1 . 0
<VALENCE> Cl - 1 . 0
<XPS_VALENCE_END>
```

用于约束电荷平衡、局域配位和可能的价态组合。

#### exact formula

Exact formula 是 oracle-like composition condition：

```text
<FORMULA> Na 1 Cl 1
```

这个 ablation 用来衡量：当组成完全已知时，模型距离理论上限还有多远。

#### known lattice

如果实验已经完成 indexing，可以额外输入晶胞：

```text
<KNOWN_LATTICE>
<LATTICE> a 5 . 6 4 0 b 5 . 6 4 0 c 5 . 6 4 0 alpha 9 0 . 0 0 beta 9 0 . 0 0 gamma 9 0 . 0 0
```

这用于对比：

```text
lattice + conditions
conditions without lattice
```

### 4.3 输出结构块

输出不是原始 CIF，而是 canonical CIF-like tokens。

示意：

```text
<CRYSTAL_START>
<FORMULA> Na 1 Cl 1
<N_SITES> 2
<SPACE_GROUP> 225
<LATTICE> a 5 . 6 4 0 b 5 . 6 4 0 c 5 . 6 4 0 alpha 9 0 . 0 0 beta 9 0 . 0 0 gamma 9 0 . 0 0
<ATOM_SITES_START>
<ATOM> Na x 0 . 0 0 0 0 y 0 . 0 0 0 0 z 0 . 0 0 0 0
<ATOM> Cl x 0 . 5 0 0 0 y 0 . 5 0 0 0 z 0 . 5 0 0 0
<ATOM_SITES_END>
<CRYSTAL_END>
```

输出可以被 `crystal_language/decode.py` 解析成结构字段，并进一步转成 `pymatgen.Structure`。

## 5. 支持的 ablation 条件

当前实现覆盖项目要求的完整 ablation 梯度：

```text
PXRD only
PXRD + element set
PXRD + XRF
PXRD + neutron
PXRD + neutron + XRF
PXRD + neutron + XRF + XPS-valence
PXRD + exact formula
lattice + conditions
conditions without lattice
```

代码中对应的 condition set：

```text
pxrd
pxrd_element
pxrd_xrf
pxrd_neutron
pxrd_neutron_xrf
pxrd_neutron_xrf_xps
pxrd_formula
```

训练时使用：

```text
--condition-set mix
--use-lattice mix
```

这样每个 batch 中随机采样不同条件组合，模拟条件 dropout。评估时则固定某一个 condition set 逐项评估。

## 9. 超长序列处理

由于大晶胞会产生很长的 token 序列，例如 80 原子结构可能接近或超过 1900 tokens，因此当前训练采用：

```text
超过 block_size 的样本直接忽略，不截断。
```

当前 `block_size=2048` 下过滤统计：

```text
train kept             = 370,672
train skipped too long = 31,028
valid kept             = 3,864
valid skipped too long = 299
```

之前做过保留率估算：

```text
block_size 1024 -> kept 222,424 / 401,700, 约 55.37%
block_size 1536 -> kept 335,496 / 401,700, 约 83.52%
block_size 2048 -> kept 370,672 / 401,700, 约 92.28%
block_size 3072 -> kept 391,646 / 401,700, 约 97.50%
block_size 4096 -> kept 398,842 / 401,700, 约 99.29%
block_size 6144 -> kept 400,774 / 401,700, 约 99.77%
block_size 8192 -> kept 401,653 / 401,700, 约 99.99%
```

当前选择 2048 的原因：

- 能保留 92% 以上训练数据；
- 注意力开销仍可接受；
- 单卡训练速度较快；
- 适合作为第一版 baseline。

后续如果要提高长晶胞覆盖率，可以考虑：

- `block_size=4096`；
- 多卡训练；
- sequence 压缩；
- symmetry-reduced / Mat2Seq-style 表示；
- 只输出 asymmetric unit。

## 11. 为什么当前模型很快

当前自回归模型比 FlowMM 快很多，原因不是它“更强”，而是它“更轻”：

- 当前模型只有约 11.5M 参数；
- 训练目标是 teacher-forcing next-token prediction；
- 输入已经是离散 token；
- 不需要每步构建周期图；
- 不需要周期邻居搜索；
- 不需要处理连续坐标流场；
- 不需要在 manifold 上做流匹配；
- vocab 很小，只有 143。

FlowMM 训练慢，是因为它在学真实三维周期几何生成；当前语言模型第一版主要是在学结构文本语法、条件到结构 token 的映射，以及常见晶体模式。

因此，当前速度快是第一版 baseline 的优点，但不能直接说明结构生成能力优于 FlowMM。最终要看：

- 语法合法率；
- parse 成功率；
- 组成一致性；
- 晶胞误差；
- StructureMatcher match rate；
- PXRD 回算相似度；
- neutron 回算相似度；
- 各 ablation 条件提升是否符合预期。

## 12. 为什么先用轻量模型

当前模型规模：

```text
6 layers, 384 hidden, 6 heads, 约 11.5M 参数
```

这是有意设计成轻量 baseline，原因：

- 先验证 pipeline；
- 快速发现序列格式、过滤、训练、解析问题；
- 避免一开始大模型昂贵地学习错误格式；
- 快速得到可比较的 ablation 结果；
- 为后续更大模型提供基线。

这并不意味着大模型不适合项目。相反，后续如果当前模型能学会基本语法但结构质量不足，就应该扩大模型。

可能的后续规模：

```text
Small:  6 layers, 384 hidden, 约 11M
Medium: 12 layers, 768 hidden, 约 80M+
Large:  16 layers, 1024 hidden, 约 200M+
```

第一轮 Top-k 评估显示：轻量模型语法能力很好，但在 `PXRD + exact formula + known lattice` 条件下 Top-50 StructureMatcher 只有 16.2%，说明单纯 V0 容量不足或搜索能力不足。因此已经完成 V1 medium 模型训练与同口径评估。medium 模型将 Top-50 StructureMatcher 提升到 26.6%，证明扩大模型容量对结构匹配有明确收益。

## 13. 下一步评估计划

当前已经进入结构生成评估阶段。评估逻辑仿照 Uni-3DAR 的 top-k 推理方式：对每个输入条件生成多个候选结构，只要前 k 个候选中有一个能通过 `StructureMatcher` 与真实结构匹配，就认为该样本在 Top-k 下解析成功。

核心定义：

```text
success@k = any(StructureMatcher(generated_i, target) == True for i in 1..k)
```

当前重点统计：

```text
Top-1 match rate
Top-20 match rate
Top-50 match rate
```

同时记录辅助指标：

```text
parse_success@k
composition_success@k
structure_success@k
candidate-level parse_valid rate
candidate-level composition_match rate
candidate-level structure_match rate
```

已实现评估脚本：

```text
crystal_language/evaluate_generation.py
```

该脚本会：

```text
1. 读取训练好的 checkpoint；
2. 读取 valid/test 的 sequence JSONL；
3. 对每个样本构造指定 condition prompt；
4. 每个样本采样 N 个候选结构；
5. 解析生成 token；
6. 转成 pymatgen.Structure；
7. 用 StructureMatcher 计算 Top-1/20/50；
8. 输出 per-sample jsonl 和 summary json。
```

为了避免生成太慢，评估脚本已优化停止逻辑：候选一旦生成 `<CRYSTAL_END>` 或 `<EOS>` 就停止，而不是强制跑满 `max_new_tokens`。

### 13.0.3 V2 site-only / constrained-CSP 改进

对比 `baselines/uni3dar` 后，发现当前 CIF-like 自回归评估和 Uni-3DAR 的 CSP/formula 口径存在明显差异：

```text

  - GT lattice 在推理端 teacher-force；

  - 即使 prompt 给了 known lattice，模型仍重新生成 lattice；
```

### 13.0.4 V3 seq2seq encoder-decoder 并行改进

V2 site-only 仍然是 decoder-only 架构：条件和目标虽然逻辑上分开，但训练时本质上仍是一个长 prompt 加目标的自回归语言模型。考虑到 Uni-3DAR 的高分结果依赖专门的条件 prefill / 条件编码机制，因此进一步新增 V3：显式 encoder-decoder 架构。

```text
encoder:

  输入 <BOS> + 已生成 site tokens
```

### 13.0.5 继续涨点的优先建议

当前最有希望继续涨点的方向按优先级排序：

```text
1. Formula-constrained decoding:
   推理时严格按照 exact formula 展开元素序列，只生成坐标。
   这样可以彻底消除 composition mismatch。

2. Coordinate bin token:
   把字符级小数改为坐标 bin token，例如 x_0000 ... x_9999。
   这会显著缩短序列并降低非法数字概率。

3. PXRD continuous encoder:
   不再只用 24 个 peak token，而是把完整谱图或插值谱图送入 1D CNN/Transformer。
   这更接近 Uni-3DAR 的条件输入方式。

4. Oversampling + reranking:
   生成 100-250 个候选，用模型分数、composition、PXRD 回算相似度、最小距离过滤重排后再取 Top-50。

5. n_sites 分桶训练/评估:
   当前大结构明显更难，应单独报告 <=20、21-40、>40 原子区间。

6. 使用更接近 Uni-3DAR 的 matcher 口径做并列报告:
   当前 matcher 比 Uni-3DAR 更严格。后续可以同时报告 strict 和 Uni-3DAR-style 两套指标。
```

如果趋势不符合预期，需要分析：

- 条件 token 是否被模型利用；
- peak token 是否过度压缩；
- 是否需要完整谱图 encoder；
- lattice token 是否泄漏或被忽略；
- 模型容量是否不足；
- 输出结构表示是否不够稳定。

## 14. 后续技术路线建议

### 14.1 第一阶段：完成当前 baseline

当前训练完成后，先做完整评估，确认：

- 能否稳定生成可解析结构；
- 各条件 ablation 是否有合理提升；
- exact formula 是否明显优于只给元素或 XRF；
- known lattice 是否明显提升晶胞相关指标；
- PXRD / neutron 回算是否有意义。

### 14.2 第二阶段：增加评估和 reranking

对每个输入生成 top-N candidates：

```text
N = 10 / 20 / 50
```

然后用物理 reward 排序：

```text
R_total =
  w1 * R_pxrd
+ w2 * R_neutron
+ w3 * R_xrf
+ w4 * R_xps_valence
+ w5 * R_structure_validity
+ w6 * R_charge_balance
+ w7 * R_stability
+ w8 * R_diversity
```

这一步与 `总体训练路线.md` 中的 Stage 3 一致。

### 14.3 第三阶段：更强条件编码

当前 PXRD / neutron 是 peak tokens，优点是简单、可解释、序列短；缺点是丢失背景、峰宽形状、弱峰和噪声信息。

后续可以引入：

```text
1D CNN / Transformer spectrum encoder
```

把完整 PXRD / neutron 曲线编码成 prefix embeddings，而不是只用 peak tokens。

### 14.4 第四阶段：更强结构表示

当前是 canonical CIF-like tokens，后续可以比较：

```text
canonical CIF-like tokens
Mat2Seq-style invariant tokens
symmetry-reduced asymmetric-unit tokens
Wyckoff-based tokens
```

目标是降低序列长度，提高不变性和语法稳定性。

### 14.5 第五阶段：扩大模型

如果第一版显示可行，可以做：

```text
12 layers / 768 hidden / block_size 2048 or 4096
```

或多卡训练更大模型。

### 14.6 第六阶段：Reward-Weighted SFT

生成候选，回算谱图和物理一致性分数，选高分样本继续 SFT：

```text
generate -> score -> select -> fine-tune
```

这比直接 RL 更稳定，也更适合论文主线。

## 16. 当前结论

目前自回归路线已经完成了从想法到训练、推理、Top-k 结构生成评估的闭环：

```text
MP+WBM 多模态结构数据
-> canonical CIF-like 序列导出
-> 条件 prompt 构造
-> 自回归 Transformer 训练
-> 超长样本过滤
-> SLURM 队列训练
-> checkpoint / tokenizer / run 目录独立管理
-> checkpoint_last.pt 训练完成
-> 初步生成 smoke test 通过
-> 500 条 valid 样本 Top-k 结构生成评估完成
```

本轮训练结果表明：

```text
轻量模型训练稳定完成，valid_loss 从 1.2580 降到 0.3395；
medium 模型训练稳定完成，valid_loss 进一步降到约 0.2220；
checkpoint 正常保存；
错误日志为空；
生成样本可以被 parser 正确解析；
medium 模型 Top-50 StructureMatcher 达到 26.6%。
```

这说明模型不仅在 teacher-forcing 层面能学习晶体结构 token 的语法和部分条件映射，也已经具备一定的真实结构生成能力。在 `PXRD + exact formula + known lattice` 这个强条件下，medium 模型能在 500 个 valid 样本中用 Top-50 采样匹配 133 个真实结构。

下一步真正决定这条路线价值的，是把评估从当前 oracle-like 条件扩展到完整 ablation 和物理 reranking，尤其是：

```text
生成结构能不能 parse
组成是否一致
晶胞是否合理
StructureMatcher 是否能匹配
PXRD / neutron 回算是否接近输入
逐步加入 XRF / XPS / neutron / formula / lattice 是否真的提升结果
```

如果这些指标表现出合理趋势，这条路线就可以作为与 FlowMM 并行的语言模型结构解析路线继续扩大模型和增强物理 reward。反之，如果它只学会了语法但结构匹配和谱图回算较差，则说明瓶颈可能在表示方式、条件编码或模型容量，需要进入下一轮改进。
